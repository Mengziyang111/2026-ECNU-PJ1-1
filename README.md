# MongoDB 问卷系统阶段二

在阶段一的账号、问卷、跳转、填写和统计功能上，增加独立题目、共享、不可变版本、历史恢复、题库和跨问卷单题统计。阶段一核心代码与接口继续使用，旧数据可保留并显式迁移。

## 安装与运行

需要 Node.js 22 或以上、MongoDB 8.x。请将 `node`、`npm`、`mongod` 加入 PATH。已锁定 MongoDB Node 驱动版本，第一次安装依赖需要联网。

Windows 下载或克隆源码后，在项目目录双击 `start.cmd`。脚本会安装依赖、复制配置，在本机27019端口启动MongoDB，再启动网页。浏览器访问 **http://127.0.0.1:3000**。关闭时在启动窗口按 Ctrl+C，脚本只停止它自己启动的数据库进程。

其他系统或使用已有 MongoDB / Atlas 时先运行 `npm ci`，复制 `.env.example` 为 `.env`，填写数据库连接与库名，再运行 `npm start`。

`.env.example` 默认仍使用 `survey_stage1`，方便在原库上升级。试用时可将 `MONGODB_DB` 改成新名字；升级旧库前先阅读迁移说明并停止业务写入。配置外部数据库时直接用 `npm start`。

## 阶段二操作路径

1. 注册或登录，在顶部进入“题目与题库”，独立创建单选、多选、文本或数字题。
2. 在题目详情查看历史。选择任意历史版本创建新版本，或另存为独立题；恢复历史会追加版本，保留来源关系。
3. 输入已注册用户名共享题目。接收者能查看与引用，修改和授权仍由创建者负责。
4. 创建题库并添加可访问题目。库内能选最新版本或历史版本，版本更新不会联动已用问卷。
5. 创建问卷，在编辑器从题目/题库选择具体版本导入，再配置属于本问卷的跳转规则。原有题也可保存为独立常用题。
6. 发布后邀请登录用户填写。题目库改版与共享撤销都不修改既有问卷快照。
7. 在题目详情查看被哪些本人问卷使用，以及同一版本在本人各问卷中的汇总；不同版本分别展示，数字显示平均值及频数分布。

可选执行 `npm run seed` 导入阶段一示例。演示账号为 `demo` / `Demo2026!`，模拟回答仅用于演示。

## 旧数据迁移

先停止应用写入，在原数据库配置下预览：

```sh
npm run migrate -- --dry-run
```

确认后执行：

```sh
npm run migrate
```

脚本先把集合导出为 Extended JSON 本地备份，再为每道旧题建立独立题目族与初始版本，补充问卷和回答的来源字段。原问卷ID、局部题ID、题目内容、跳转、revision、答案值、path、匿名标记和去重凭证保留。再次执行不会重复建立题目。详细步骤、兼容限制与恢复办法见 [迁移说明](docs/MIGRATION.md)。

## 测试

先启动MongoDB，再在项目目录运行 `npm test`。

自动测试使用隔离数据库，清理前检查测试库名，不清空业务库。保留阶段一原有43项测试，新增题目复用、共享、版本、题库、统计、权限与迁移测试。步骤、输入、期望结果和实际输出见 [测试文档](docs/TESTS.md) 与 `docs/test-results.tap`；浏览器验收另存 `docs/browser-results.json`。

## 权限与统计口径

题目共享授予阅读和引用权限，不开放其他人的问卷内容或回答。使用反查仅列出当前账号管理的问卷，其他用户引用只显示数量。跨问卷统计也只覆盖当前账号有权管理的问卷；按不可变版本ID分组，不按标题、问卷局部题ID或选项文字猜测合并。同一问卷同一版本只能引用一次。

版本内容不可原位修改。标题、类型、选项、必答和校验约束来自固定版本；跳转规则属于问卷自身。撤销共享不销毁已经使用的快照，但会阻止继续向新问卷引用。默认仅绑定本机地址，公网部署需另行配置HTTPS及运行环境。

## 配置

| 变量 | 默认值 |
| --- | --- |
| `MONGODB_URI` | `mongodb://127.0.0.1:27019` |
| `MONGODB_DB` | `survey_stage1` |
| `HOST` | `127.0.0.1` |
| `PORT` | `3000` |
| `COOKIE_SECURE` | `false`，HTTPS环境设为true |
